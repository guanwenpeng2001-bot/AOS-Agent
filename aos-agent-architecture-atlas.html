04 · Runtime flow

一次任务是怎么跑起来的

Agent 不是模型回答一次就结束。用户在 TUI、print/headless、RPC 或 SDK 提交的 prompt 只是输入；统一入口适配器必须先把它和 Session、workspace、Goal、route 等上下文转换为持久 TaskEnvelope。Role 决定“谁来做、怎么做”，Task 决定“做什么、如何验收”，Scheduler 决定“何时执行、是否并行、怎样汇合”。

Surface prompt：输入先进入统一适配器

TUI、print/headless、RPC 和 SDK 只提交版本化输入命令。入口适配器结合 Session、workspace、可选 Goal、route 和显式验收要求创建 TaskEnvelope；任何入口都不能直接绕过 Task / Binding 调用 Agent Loop。

产品纵向链路：TUI / print / RPC / SDK prompt → Prompt Task Adapter → persisted TaskEnvelope → RoleRevision + ModelProfile + Policy → Resolver → immutable AgentBinding → Dispatch → TaskExecutorProvider → Attempt → BindingEpoch → AgentHarness / Context / Tool → AttemptReceipt → TaskResult → Host RunReceipt。Goal 可关联 Task / TaskGraph，但 prompt、Goal 和 Task 不是同一对象。只有 Agent 类 Provider 创建或绑定 AgentInstance；Operation Worker 不进入 AgentInstance。

05 · Memory & safety

记忆和安全：一个负责记住，一个负责别越界

记忆属于上下文系统；安全不能靠模型自觉，必须在工具真正执行前后有本地可验证的边界。

记忆的五个层次

工作、会话和项目记忆属于当前 Agent 闭环；Child Agent 的独立记忆以及长期记忆 / RAG 属于后续平台能力。Sandbox Operation Worker 不运行 Agent Loop，因此不拥有 Agent Memory。

06 · DeepSeek contrast

DeepSeek Harness 与 AOS 不是同一层的替代品

DeepSeek 解决“如何把运行时做成可替换插件产品”；AOS 解决“如何把一个开发 Agent 和它的执行过程做成可治理、可恢复、可审计的运行单元”。两者可以互相借鉴，不是二选一。

DeepSeek

组合能力很强

Cordis 把 Agent、Session、LLM、Tools、Policy、Persistence 和 UI 放进可卸载的 plugin tree。Profiles、bundles 和 patch 可以在启动时重组整棵运行时。

AOS

控制面合同更明确

RunReceipt、AttemptReceipt / TaskResult、Model / Capability / Policy / Sandbox binding、Audit / Replay 和 remote-neutral operation 是显式边界，不能被插件绕过。

共同方向

都在远离一次性脚本

两者都把事件、会话、工具边界、取消和恢复做成运行时结构。差别在于 DeepSeek 更偏可组合内核，AOS 更偏执行控制面。

10 · Glossary

把几个容易混淆的词分开

Agent Loop

模型判断下一步、调用工具、观察结果并继续的循环。

Run

Host 接受的一次有 ID、有状态、有起点和终点的可治理执行；终态由 Host 唯一 RunReceipt 表达。

Task

Goal / TaskGraph 中可验收的工作单元。Task 必须在 Binding 解析前存在；Graph 节点就是 Task。

RoleDefinition / RoleRevision

Role 描述“谁来做、怎么做”：persona、指令、能力选择器、上下文 / 记忆 / 执行 / 结果策略和 ModelProfile 引用。Revision 不可变；Role 不保存 secret。

ModelProfile

可复用的 provider、model、effort、service tier、fallback 和 budget 配置。Role 只引用它，凭据由运行时安全边界解析。

Role Resolver

消费已存在的 Task，并按 Managed Lock、Global、Project、path、Goal、Task、Run 层级解析 RoleRevision、ModelProfile、Policy、预算和来源冲突。

AgentBinding

Resolver 输出的不可变执行配置：taskId、Role / ModelProfile revision、能力、上下文、策略、预算和来源指纹。

BindingEpoch

同一 Attempt 内一次 AgentBinding 激活的不可变区间。Attempt 启动时创建 ordinal 0；Mode switch 不创建新 Attempt，只在安全边界追加更大 ordinal 的 Epoch。每个 Turn、Step、工具 intent、Context Snapshot 和事件固定引用一个 Epoch。

AgentInstance

Agent 类执行者的稳定实例身份。Dispatch 先选择 TaskExecutorProvider；只有 Agent 类 Provider 才创建或绑定实例。Operation Worker 没有 AgentInstance。

Mode

产品层对 RoleDefinition / RoleRevision 的称呼和激活方式。用户创建的 Mode 会持久化，模型设置保存为 ModelProfile；不再建立重复的 ModeDefinition 运行模型。

Mode switch

保留同一 Task、Attempt 和 AgentInstance，在 Turn / Step 安全边界激活新 BindingEpoch；不创建子 Agent。

Spawn Agent

创建新 Task、Context 和 Dispatch，再由 Agent 类 Provider 创建或绑定新 AgentInstance。它不等同于 Mode 切换。

Context

某次模型请求实际能看到的规则、消息、文件、工具和记忆。

Capability

可以发现和调用的工具、MCP、Skill 或 Extension。

Policy

决定某类操作 allow、ask 还是 deny 的规则系统。

Sandbox

让 Policy 在 OS、VM、容器或远程环境中真正成立的执行边界。SandboxProvider 接口和 gondolin-local 本地 VM 示例已有；真实后台 Worker、远程及多租户执行环境待补。

Transport

同一套 Host 命令换一种连线方式。不改变 Run 语义。

Sandbox Provider

提供执行边界的 Provider，可以是进程内、VM 或其他后端。它负责落实 Policy，不等于后台 Worker，也不拥有任务调度权。

Sandbox Operation Worker

拥有独立生命周期，执行 Host 授权的 bounded Sandbox operation，并返回 WorkerReceipt。它不是 TaskExecutorProvider，不创建 AgentInstance，不运行 ModelRuntime、Agent Loop，也不拥有 Session 文件或 Run 终态。

Agent Runtime Host

在独立进程中承载 Child Agent 的 ModelRuntime、Context、Agent Loop、Transcript 和生命周期。它可以成为 Native Subagent provider，但不是 Sandbox Operation Worker。

Native Subagent

AOS 自己管理的 Child Agent。它可以选择 in-process、fork、Agent Runtime Host、ACP 或 SDK provider，并复用 AOS 的 Run、Context 和 Policy 合同；工具操作可另行调用 Operation Worker。

External Agent Adapter

把冻结后的 AOS Binding 翻译给 Claude、Codex、ACP 等外部 Agent / Executor 的边界。它不是第二套 Agent Loop，也不是 Native Subagent。

Worker Supervisor

负责 Sandbox Operation Worker 的启动、私有 RPC、心跳、失联判定、取消、回收和 Reclaim。

Task Graph

把大目标拆成有依赖关系的 Task 节点，并记录节点状态。Run、Dispatch 和 Attempt 是 Task 的执行记录；Task Graph v1 还不负责 Queue、Claim 或实际调度。

TaskExecutorProvider

Scheduler 面向的统一任务执行者合同。Dispatch 先选择 Provider，Provider 再创建 Attempt 并返回 AttemptReceipt；Agent 类 Provider 才创建或绑定 AgentInstance。

Scheduler

读取可执行节点，通过 TaskExecutorProvider 选择执行者，管理 Queue、Claim、并发预算、Handoff 和结果汇合；不硬依赖 Sandbox Operation Worker。

Adapter

把 AOS 冻结 binding 翻译成外部 Agent 的原生启动方式。不是第二套 Loop。

Goal

用户希望完成的可验收目标。它可以拆成 Plan、Todo、Task 和多个 Run，但不等于某一次模型调用。

Attempt

TaskExecutorProvider 对某次 Dispatch 的具体执行尝试。它有 fencing、恢复语义和一个或多个有序 BindingEpoch。

Dispatch

控制面把 Task 与已解析 AgentBinding 交给某个 TaskExecutorProvider 的耐久记录；Operation Worker 只是 Attempt 内可调用的工具服务。

Lease

绑定到任务的短期权限或执行所有权。可以续租、撤销，过期后不能继续使用。

Handoff

一个执行者把任务、状态和结果交给另一个执行者继续处理的显式过程。

CapabilityPack

一组可版本化的工具、Skill、MCP、模型和策略选择，解析后进入不可变 Binding。

Artifact

代码变更、文件、日志、测试结果或 PR 等可引用、可校验、可交付的结果对象。

WorkerReceipt

Operation Worker 对一次 bounded Sandbox operation 的结果；不能结算 Attempt、Task 或 Run。

AttemptReceipt

TaskExecutorProvider 对一次 Attempt 的终态记录，可引用 WorkerReceipt、Artifact、用量和副作用状态。

TaskResult

从一个或多个已验证 AttemptReceipt 验收或汇合出的结构化任务结果：summary、artifacts、diff、tests、evidence、error、provenance 和 validation。纯文本“已完成”不算完整结果。

RunReceipt

Host terminal gate 写入的唯一 Run 终态记录，可引用 TaskResult 和 AttemptReceipt；下层执行者不能写入或改写。
