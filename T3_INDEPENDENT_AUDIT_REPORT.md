# T3 Independent Completeness Audit

## Scope and result

I read the architecture atlas, external-agent connector PR, and implementation plan in full and audited the merged T3A-T3E code against every T3 requirement, acceptance criterion, invariant, default-off rule, and exit gate at implementation-plan lines 500-532. The repaired implementation satisfies those T3 requirements. Connector execution, activation control-plane work, and all other T4+ behavior remain out of scope.

## Full-suite stability evidence

- Worker heartbeat stall: the original fixture delayed heartbeat 1 by 10 ms, allowing the unchanged 60 ms loss watchdog to win under load. Batching `ready` and heartbeat 1 proves acceptance before later stall without widening the watchdog.
- Worker readiness: `handles slow readiness and bounds the ready timeout` exhausted the shared 2,000 ms process-start allowance under parallel child load. The general fixture allowance is now 10,000 ms, while the dedicated readiness-timeout assertion remains 40 ms.
- Footer debounce: `debounces rapid reftable updates into a single async refresh` timed out after 10,000 ms because same-size rapid writes can evade Windows `watchFile` timestamp granularity. The renamed unit test, `debounces rapid reftable refresh requests into a single async refresh`, calls the scheduling seam; separate tests still exercise real filesystem watching.
- RPC automation: `emits accepted response before run.started, then run.event* and exactly one terminal` exceeded Vitest's implicit 1,000 ms polling budget under full load. Its bounded settlement wait is 10,000 ms; order and exactly-one-terminal assertions are unchanged.
- TCP idempotency: `retries clientRequestId on the real TCP Host without creating a second run` likewise exceeded the implicit 1,000 ms polling budget. Its 10,000 ms wait changes only the test allowance; duplicate-run and terminal-count assertions are unchanged.
- RPC stdio/TCP transcript: a full-suite run exposed the shared `waitForRecord` 1,000 ms default; the exact failed case name was not retained, so none is inferred here. The helper now uses `RUN_SETTLEMENT_TIMEOUT_MS = 10_000`; all four transcript tests passed individually and the later full suite passed.
